# 上下文规则 - Layer 2

## 💻 代码开发规则

### 文件结构和包含
- **统一头文件**: 新文件优先包含 `CoreMinimal.hpp`
- **平台抽象**: 使用 `PlatformCommon.h` 而非直接包含平台头文件
- **避免循环依赖**: 保持头文件轻量，注意包含顺序

### 代码风格约定
- **条件编译**: 使用 `#if ANDROID` 而非 `#ifdef ANDROID`
- **命名规范**: 严格遵循现有代码的命名约定
- **注释策略**: 除非明确要求，否则不添加注释
- **函数命名**: 保持与现有代码风格一致

### 平台特定代码处理
- **位置**: 平台特定代码放在对应的平台头文件中
- **抽象**: 通过 `PlatformCommon.h` 提供统一接口
- **避免**: 源文件中直接定义平台相关宏

## 🛠️ 构建系统规则

### 统一脚本使用
- **优先使用**: `build.bat [platform]` 和 `vcpkg.bat [platform]`
- **支持平台**: windows, macos, linux, android, mingw
- **自动检测**: 脚本支持自动平台检测，但仍建议明确指定平台

### 构建输出管理
- **桌面端**: 输出到 `build/{platform}/bin/`
- **Android**: 输出到 `android/app/build/outputs/apk/`
- **清理策略**: 必要时可删除整个 `build/` 目录重新构建

### 构建问题排查
1. **依赖检查**: 确认 `./vcpkg.[bat|sh] [platform]` 已执行
2. **清理重建**: 删除 `build/` 目录后重新构建
3. **日志分析**: 查看编译输出定位具体错误
4. **平台验证**: 确保在正确的平台上构建

## 🧪 测试和验证规则

### 编译验证
- **每次修改**: 代码修改后必须验证编译成功
- **多平台**: 跨平台修改需要在每个目标平台测试
- **清理测试**: 必要时进行清理构建验证

### 功能验证
- **重要修改**: 重要功能修改后必须运行应用程序测试
- **平台特定**: 平台特定修改需要在对应平台验证
- **回归测试**: 确保修改不影响现有功能

### 性能考虑
- **构建优化**: 生产构建使用优化选项
- **调试信息**: 开发构建保留调试信息
- **包大小**: Android构建注意包大小控制

## 📂 项目结构理解

### 核心目录
- `src/Runtime/`: 核心运行时代码
- `src/Runtime/Platform/`: 平台特定代码
- `src/Vulkan/`: Vulkan渲染相关代码
- `src/Assets/`: 资源管理代码
- `src/Common/`: 通用代码，包含 `CoreMinimal.hpp`

### 资源文件
- `assets/`: 模型、纹理等资源文件
- `android/`: Android项目目录
- `build/`: 构建输出目录

### 关键文件
- `src/Common/CoreMinimal.hpp`: 统一头文件
- `src/Runtime/Platform/PlatformCommon.h`: 平台抽象层
- `vcpkg.json`: 依赖定义
- `CMakeLists.txt`: 构建配置

## 🚨 常见陷阱和解决方案

### 头文件问题
- **问题**: 找不到头文件或重复包含
- **解决**: 确保使用 `CoreMinimal.hpp`，检查包含顺序

### 平台编译错误
- **问题**: 平台特定代码编译失败
- **解决**: 检查 `PlatformCommon.h` 抽象，使用正确的条件编译

### 构建脚本问题
- **问题**: 构建脚本执行失败
- **解决**: 检查依赖安装，确认平台参数正确

# SCAD 场景生成指引（AGENT 向）

本文沉淀 `assets/scad/` 下场景（`office` → `airport` → `habor_city` → `habor_city_hd`）的生成经验，
供后续用 LLM/AGENT 生成新场景时直接参照。引擎加载器的实现细节见 `AGENT_GUIDE/SCADLoader.md`，
本文只讲**怎么写出一个好场景**。

## 1. 定位与参考场景

| 场景 | 尺度 | 特点 | 适合参考 |
|------|------|------|----------|
| `office.scad` | 人尺度室内 | 单层办公室、家具、POI 锚点首创 | 室内家具/锚点命名 |
| `airport.scad` | 人尺度室内+外 | 切顶航站楼、地勤车队、POI 体系成熟 | 室内功能分区、柜台/设施件 |
| `habor_city.scad` | 微缩沙盘（672x508） | 全城鸟瞰、12x6 街区、组团复用 | 大范围城市布局、参数化组团 |
| `habor_city_hd.scad` | 人尺度城市（172x158） | 街区+海滨港区、63 个游戏 POI | 人尺度街景、交通/经营锚点体系 |

新场景先回答三个问题：**什么尺度**（人尺度 1 单位=1 米，还是沙盘微缩）、**多大范围**（人尺度下
全图建议 ≤ 200x200，否则三角形和模块数失控）、**POI 服务什么玩法**（决定锚点类别表）。

## 2. 引擎子集红线（写之前必读）

只用 SCADLoader 已支持的特性（完整清单见 `AGENT_GUIDE/SCADLoader.md`）：

- **禁用**：`offset` / `projection` / `import` / `surface`；`resize` 是 no-op；`minkowski` 退化为 union。
- **慎用**：`difference` / `intersection` 走 Manifold 真布尔，有实际开销且正侧多色时只保留第一色——
  能用"画家叠层"（薄片叠在面上，z 错开 0.01~0.02）就不要做布尔。全场景做到 **0 difference** 是常态。
- **可用**：全部 3D/2D 图元、`text()`（FreeType 含 CJK）、`linear_extrude` / `rotate_extrude`、
  `hull`（船头/流线体很好用）、list comprehension、`for` 多绑定笛卡尔积、模块内变量赋值、
  默认参/关键字参、三元表达式。
- **材质**：`color` 不透明 → Lambertian；**alpha < 0.99 → Dielectric 玻璃**。玻璃门/候车亭/围栏网
  用 4 分量色（如 `[0.55,0.72,0.85,0.35]`），不透明窗户用浅蓝实色更便宜。
- **变量是动态作用域**，模块体可见调用链变量；`$fn` 天然动态生效。
- 几何按 user module 调用树重建节点层级：**每个 module 调用实例 = 一个场景节点**，直属几何按颜色
  分桶合并，单节点超过 16 个颜色会拆分。模块内配色控制在十种以内。

## 3. 全局约定（与现有场景对齐，必须遵守）

- **坐标系**：OpenSCAD Z-up；约定 +y 为"北/远端"，-y 为"南/近端（海/入口）"。
- **朝向**：所有带朝向的 module 一律 `front = -y`，布局处用 `rotate` 调朝向。
- **落地**：所有落地件**底面 z=0**，由布局处 translate 到所在台面标高。
- **标高体系**（人尺度场景，与 office/airport 的 kGroundY 对齐）：
  - 路面/基准地面顶 `GZT = 0.15`
  - 人行道/街区台面顶 `WZT = 0.30`（路缘石顶 0.22 过渡）
  - 海面顶 `SEAZ = -0.50`，展台底座再往下
  - 路面标线 z = GZT + 0.012~0.016，台面标线/砖缝 + 0.006~0.016，**相邻叠层错开 ≥0.01 防 z-fight**
- **伪随机**：`function rnd(i, m) = let (k = (i * 73 + 31) % 97, kp = (k < 0) ? k + 97 : k) (kp * 13 + ((i % 7 + 7) % 7)) % m;`
  确定性散列，引擎与 OpenSCAD 渲染一致；配色板用 `function xxx_c(i) = [[...],[...]][rnd(i,n)]`。
- **配色**：全部大写常量集中在文件头（`ROADC/WALKC/GLASSL/...`），模块内不出现裸 RGB（个别局部色除外）。
- **命名前缀**：`ground_* road_* part_* bldg_* prop_* furn_* veh_* boat_* nature_* block_* zone_*`；
  POI 锚点用类别前缀 + 两位编号（见 §5）。
- **$fn 预算**：全局 `$fn = 12`；树冠球 6~8、车轮 9~10、小圆柱 6~7、大圆台 8~9。能低则低。

## 4. 文件结构模板（按此顺序写）

```
1. 头注释：场景说明 + 总平面文字图 + POI 锚点类别表（数量、用途）
2. $fn / 标高常量 / 路宽常量
3. 配色表 + rnd/调色板函数 + boxc/slab 工具
4. 植被 nature_*
5. 街道小品 prop_*（含锚点专用小几何：井盖/门垫/挡轮石/装卸框）
6. 地面与道路 ground_* / road_*
7. 建筑公共件 part_*（门/窗/遮阳棚/女儿墙/屋顶设备/招牌字/雨棚/机坪）
8. 建筑库 bldg_*（每栋：体块→门窗→招牌→屋顶，前后 30~60 行）
9. 车辆 veh_* / 船舶 boat_* / 专项设施（吊机/集装箱/沙滩件）
10. 街区组团 block_*（含台面 pad，内容置于 z=WZT，局部坐标）
11. 区域 zone_*（海滨/码头/背景带等大区，全局坐标）
12. 路网/路缘/信号灯/车流总装 module
13. POI 锚点定义（一行一个 wrapper module）+ poi_all() 集中布点
14. 顶层总装：地面 → 路网 → 组团 → 区域 → 车流 → poi_all()
```

复用优先：植被/车辆/船舶/小品模块在 `habor_city(.hd)` 与 `airport` 间基本可以直接搬运（注意尺度）。

## 5. POI 锚点规范（游戏开发对接）

锚点机制：**锚点 = 具名 user module**，加载后节点名 = module 名，`WorldTranslation` = 布点坐标。
游戏侧按名字前缀归类（参照 OfficeMap / AirportMap 的做法）。

规则（缺一不可）：

1. **锚点调用 `translate(...)` 必须在 `rotate(...)` 外层**，否则 WorldTranslation 不对。
2. 每个锚点 module **恰好被调用一次**；同类多实例就定义 `xxx_01/xxx_02/...` 多个 module。
3. 锚点**自带少量几何**（空节点可能被剔除），且语义自洽：
   - 路网节点 → 井盖；生成点 → 路缘道钉；停车位 → 挡轮石；装卸点 → 黄色斜纹框；
   - 业务入口 → 门垫（建筑本体保持独立 module，避免几何重复）；
   - 设施型锚点（候车亭/加油位/喷泉/风机/机坪）→ 直接以设施本体作为锚点几何，
     此时**对应建筑/组团 module 里不要再画一份**（habor_city_hd 的直升机坪就是从医院/警局
     建筑里剥离出来给 `heli_*` 锚点的）。
4. 屋顶/高台锚点要计算**绝对标高**（台面 WZT + 建筑高度 + 屋面层厚），写注释留痕。
5. 在文件头注释里维护**锚点类别表**（前缀、数量、玩法语义），游戏侧照表消费。

habor_city_hd 的类别表（交通/配送 + 城市经营双玩法）可直接套用：
`node_`(路口图节点) `spawn_`(车辆生成) `stop_`(公交) `park_`(车位) `fuel_` `heli_` `dock_`(泊位)
`load_`(装卸) + 业务类 `hospital_ police_ hotel_ market_ cafe_ burger_ barber_ gas_ warehouse_
shop_ apt_ house_ court_ beach_ pier_ plaza_ turbine_`。

## 6. 性能预算

参考数据（RTX 5070 Ti）：`acient_city` ~155k 三角形 / 解析 40ms / 上传 250ms，体感顺滑；
人尺度城市目标控制在 **15~30 万三角形**。

成本大户与对策：

- **球体**：树冠是大头。`$fn=6` 的 sphere ≈ 50 三角形，全场景树控制在 ~100 棵内。
- **text()**：一个字形 100~400 三角形。招牌字号 0.4~0.8、一处 ≤ 12 字符，全场景 ≤ 25 处。
- **薄片阵列**（砖缝/泊位线/栏杆/虚线）：单片 12 三角形便宜，但要乘数量；砖缝间距 ≥2.4，
  围栏立杆间距 ≥2.5，虚线步长 4。
- **透明体**（Dielectric）有折射开销，玻璃幕墙能用实色 `GLASSL` 就不用 alpha。
- 单 module 直属几何颜色 ≤16 种，超了会拆 `__render` 子节点（无害但层级变丑）。

## 7. 造型技巧速查

- **画家叠层代替布尔**：路面→标线→井盖、球场→禁区→白线→中圈（圈内再叠回底色"挖洞"）、
  机坪灰底→白环→蓝芯→H 字，全部靠 z 递增 0.01~0.02 叠出来。
- **四板女儿墙**：四条 box 拼框，代替 difference 挖屋顶。
- **坡顶/山墙**：`rotate([90,0,90]) linear_extrude(L, center=true) polygon(三角形)`。
- **hull 船头**：两个截面 box hull 出收分，船/快艇通用。
- **文字居中**：`translate([-len(label) * size * 0.36, ...])` 经验系数 0.36；
  立面字外移 0.16~0.32 防共面。
- **条纹遮阳棚**：n 片交替色小板 `rotate([26,0,0])` 斜挑 + 前缘横杆。
- **道路系统**：沥青整条铺，虚线按"路口间区段"列表绘制（避开路口与斑马线带）；
  T 字路口**不要画没有路的那条腿的斑马线**；路缘石 0.3x0.22 沿台面边。
- **旋转后的坐标换算**：`rotate(-90)` 下局部 `(x,y)` → 全局 `(y,-x)`。布局表先在注释里写清
  全局坐标，再换算局部，最后用脚本/心算复核边界。

## 8. 生成工序（推荐流程）

1. **参考图分析**：列出建筑清单、地标物、配色基调、标志性小品（示意图里"有什么"先穷举）。
2. **布局草图**：在头注释里写总平面文字图——路网（横纵路坐标）、街区划分（x/y 区间表）、
  分区职能。所有后续坐标都从这张表推。
3. **自底向上实现**：小品 → 部件 → 建筑 → 组团 → 区域 → 总装。每个 module 写完即检查
  尺寸边界是否落在所属台面内。
4. **碰撞复核**：重点排查 a) 组团内建筑 vs 小品/灯杆，b) 总装层 prop（路灯/信号灯）落点
  是否插进组团内容，c) 锚点与建筑几何重复。
5. **静态自检**：跑括号配平 / module 引用闭环 / 禁用特性 / POI 唯一性检查（正则即可：
  `module 名` 集合 vs 调用集合 vs 内建白名单；POI 前缀 `\w+_\d+` 每个恰好调用一次；
  搜 `offset|projection|import|surface|resize|minkowski`）。
6. **渲染验证**：`gnb shot --target ScadStudio --scene assets/scad/<scene>.scad --frames 60`，
  读 `out/build/<preset>/screenshots/agent_validation.jpg` 肉眼检查；关注 z-fight 闪面、
  黑面（polyhedron winding）、文字方向、漂浮/穿插。
7. **日志检查**：`SCAD:` 前缀 warning 数应为 0；`gkNextUnitTests "[Scad]"` 不应回归。

## 9. 常见坑 checklist

- [ ] 共面 z-fight：相邻台面/坡道/标线没有错开 z（≥0.01）。
- [ ] T 字路口画了四条腿的斑马线。
- [ ] 总装层路灯/信号灯插进了组团里的建筑（两层坐标系各自排查）。
- [ ] 锚点几何与建筑里画的同一设施重复（机坪、候车亭最易中招）。
- [ ] 锚点 translate 写在 rotate 内层，WorldTranslation 错位。
- [ ] 屋顶锚点忘了加台面高 WZT，悬空或陷入屋面。
- [ ] `rnd()` 输入负数没走绝对值保护（用本文 §3 的实现即可）。
- [ ] 玻璃用了不必要的 alpha（Dielectric 开销）；或反过来，门/亭玻璃忘了 alpha 显得像实墙。
- [ ] 树/文字失控导致三角形超预算（先数数再下笔）。
- [ ] 模块尺寸超出台面边界（写 module 时在注释标出占地 x/y 区间）。

## 10. 交付清单

一个合格的场景 PR 应包含：`assets/scad/<scene>.scad`（头注释含总平面图 + POI 表）、
`gnb shot` 截图肉眼确认记录、SCAD warning = 0、（若新增锚点类别）游戏侧消费约定说明。

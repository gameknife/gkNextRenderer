# #00018 AIService Agent 化 — Phase 2：本地 llama provider

## 做了什么

接入 gnb 启动的本地 llama-server（OpenAI 兼容），引擎与 `gnb llm` 共用同一个模型进程。

### 新增 PID 文件解析

`Engine/Runtime/Subsystems/AI/LlamaPidFile.{hpp,cpp}` — 解析 `external/llm/run/server.pid`（gnb 写入的 7 行结构）：第 1 行 pid、第 2 行 host、第 3 行 port、第 4 行 model id；后续行为 ctx/parallel/reasoning 元数据。CRLF / 部分写入 / 非数字 / 空模型 都返回 invalid 而非崩溃。

### 新增 LocalLlama provider

`FLocalLlamaProvider`（在 AIService.cpp 内）：
- Initialize：读 `localllm` config 段（endpoint / model / pidFile / autoDiscoverPid），autoDiscoverPid=true 时立即 `RefreshFromPidFile`
- Chat：每次调用前重读 PID（让 `gnb llm serve --model <id>` 切模型对引擎透明），用 BuildOpenAIChatRequestBody → POST `/v1/chat/completions` → ParseOpenAIChatResponse
- Generate：thin wrapper 调 Chat（与 Phase 1 其他 provider 统一）
- 即使 server 没跑也算 "configured"（只要有 fallback endpoint），错误推迟到 Chat 时返回

### 枚举 / 工厂 / 字符串映射

- `EAIProviderType::LocalLlama` 新增
- `CreateProvider` / `ProviderTypeToString`（→ `"localllm"`）/ `StringToProviderType`（接受 `localllm` / `local` / `llama`）/ `GetAvailableProviders`（LocalLlama 排在首位）全部更新

### 配置变更

`assets/configs/ai_config.json` 默认 provider 改为 `"localllm"`，新增 `localllm` 段，旧 provider 段保持不变（用户可手动切回）。

`AGENTS.md` 在 "Local LLM (gnb llm)" 节追加一段说明引擎集成。

## 风险与遗留

- **未实战打过真实 llama-server**：本期没启动 `gnb llm serve`（避免下载模型等不稳定操作）。Phase 3 引入 agent loop 时会自然覆盖这条端到端链路
- **`IsProviderConfigured` 总是 true**：LocalLlama 只看 endpoint 是否非空，不探测 server 可达性。AI Panel 会显示 "Ready" 但 Chat 时才报连接错误。可接受 —— 探测会引入启动延迟和心跳开销
- **PID 文件被并发写入的窗口**：gnb 切模型时 PID 文件会被截断重写。当前实现：解析失败保留上次成功的 endpoint/model。窗口短（gnb 用临时文件 + rename），实际遇到再加重试
- **autoDiscoverPid 重新读 PID 在每次 Chat 都跑**：是 stat + 小文件 read，开销可忽略；agent loop 高频调用时若成为热点再加 cache + ttl

## 做了什么

- 按 `docs/WebRTC-RemotePlay-Design.md` 推进 Remote Play Phase 1：从 Phase 0 signaling 骨架升级为最小视频端到端链路。
- 新增 `FRemoteSession`：每个浏览器 request 创建一个 `rtc::PeerConnection`，添加 H.264 video track，生成 offer，经 WebSocket 接收 browser answer，并在 track open 后按 `--remote-fps` 发送 RTP video frame。
- 新增 `FOpenH264Encoder`：接入 vcpkg `openh264`，把 I420 帧编码为 H.264 Annex-B NALU，首帧强制 IDR，后续定期 IDR。
- 新增 `FFrameSource`：生成 640x360 等 remote 分辨率的动态 I420 测试图样，作为 Phase 1 的稳定视频源；真实 swapchain capture 留到后续阶段。
- 更新浏览器客户端 `assets/remote/index.html`：创建 `RTCPeerConnection`，处理 offer/answer/candidate，绑定 `<video>`，并显示 peer state、stream state、video bytes。
- CMake 的 remote feature 现在同时要求 `libdatachannel`、`cpp-httplib`、`openh264`，Windows 下直接查找 vcpkg installed 头文件和 release/debug 静态库，不再依赖外部 `pkg-config` 可执行文件。

## 风险和遗留

- 当前视频源是动态测试图样，还不是引擎 swapchain/capture 帧；后续阶段需要接入真实帧源并处理 RGB->I420/GPU readback 或硬件编码路径。
- 输入 DataChannel、鼠标键盘注入、鉴权、TURN、码率/分辨率自适应仍未实现。
- 服务仍是 LAN-only 未鉴权模式，不能暴露到公网。

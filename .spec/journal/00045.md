## 做了什么

改进 `gnb todo next --wait` 对 `.spec/TODO.md` 修改的响应：

- 使用 `fsnotify` 监听 `.spec` 目录，覆盖直接写入和临时文件 rename 保存。
- 收到 TODO 相关事件后用 25ms debounce 合并连续写事件并立即重读。
- 保留 `--poll` 作为 watcher 不可用或事件遗漏时的可靠兜底。
- 增加短暂解析重试，避免编辑器保存过程中读到临时缺失或未完整内容。
- watcher 安装后立即二次读取，关闭初次读取与开始监听之间的竞态窗口。
- 更新命令帮助，明确 `--poll` 是 fallback interval。
- 强化测试：把轮询间隔设为 1 秒，断言 TODO 修改后 700ms 内返回，证明走的是文件通知。

## 风险/遗留

- watcher 初始化失败时会静默退回轮询，命令功能不受影响，但响应速度回到 `--poll` 间隔。
- `go test ./...` 在 Windows 的既有 `TestUntarPreservesSymlink` 因当前进程无符号链接权限失败；其余包通过。

# #00020 AIService Agent 化 — Phase 4：通用知识工具（C++ 移植 gnb）

## 做了什么

把 gnb dashboard chat 那套"让 LLM 自主探索仓库"的工具集 1:1 移植到引擎 C++，作为 agent loop 可注册的 `IAITool` 实现。无外部依赖（仅 `git` 命令行 + `std::filesystem`）。

### 新增工具

| 工具 | 行为 |
| --- | --- |
| `list_dir` | 仓库内目录列表，目录排前；max_entries 1-200，默认 50 |
| `find_files` | `git ls-files` 后 substring 匹配（大小写不敏感），含父目录路径；max_results 1-300，默认 80 |
| `search_text` | 遍历 ls-files 文件，line scan 含查询子串（case-insensitive），输出 `path:line:trimmed`；512 KiB 单文件上限 + 二进制跳过 |
| `find_symbol` | C/C++ 符号：定义 `class/struct/enum class NAME`、声明（带 `;` 无 `{`）、实现 `NAME::method`、引用；分四组排序输出；字符串字面量内的匹配被过滤 |
| `read_file` | 文本文件读，2 MiB 磁盘上限 + 256~24000 char 输出截断 + 二进制跳过 |
| `git_log` | `git log -n N --date=short --name-status --format=---COMMIT---…`；limit 1-30 |
| `git_show` | `git show --stat --name-status --format=fuller REF`；1000~24000 char 截断 |
| `run_cmd` | 白名单：`git {status,diff,log,show,ls-files,rev-parse,branch}` + `gnb todo {list,show,next}`；拒绝 shell metachar `\r\n;&\|<>` |

### 安全沙箱（`PathSandbox.{hpp,cpp}`）

- `SafeRepoPath(repoRoot, rel)`：`lexically_normal` 拒绝绝对路径 / 起始 `..` / 解析后不在 root 前缀下；返回 host-style 绝对路径
- `IsProbablyBinary(data)`：前 4 KiB 含 NUL 即视为二进制
- `IsSourceLikePath(path)`：扩展名属于 C/C++ 家族（`.c .cc .cpp .cxx .h .hh .hpp .hxx .inl .ipp .mm .m`，大小写不敏感）

### 进程执行

`RunCommandCapture(cwd, cmd, args)` — 跨平台 `_popen`/`popen`，每个 arg 走 ShellQuote（Windows 双引号转义、POSIX 单引号转义），输出捕获 stderr 合并到 stdout，硬上限 `2 * 24000` chars 防止 OOM。

### 注册接口

```cpp
FRepoToolsOptions opt;
opt.repoRoot = Utilities::FileHelper::GetPlatformFilePath(".");
RegisterRepoTools(reg, opt);
```

每工具可单独通过 `enableX=false` 关掉（游戏 runtime 可能想只暴露 read_file）。

### 测试覆盖（8 case / 50 断言）

- `SafeRepoPath`：合法路径、`..` 逃逸、绝对路径、子目录 `..` 还在 root 内的合法情况
- `IsProbablyBinary`：空 / 文本 / 含 NUL
- `IsSourceLikePath`：常见扩展名 + 大小写不敏感 + 无扩展名 + 非源码
- `list_dir`：目录排前 / max_entries 截断 / 路径逃逸 ERROR / 不存在 ERROR
- `read_file`：正常读 / 二进制跳过 / 空路径 ERROR / 逃逸 ERROR
- `run_cmd`：非白名单命令 / 白名单命令但非允许子命令 / shell metachar / 空 cmd
- `find_files`/`search_text` 必填 query 校验
- `RegisterRepoTools` 按 enable flag 注册子集

## 风险与遗留

- **`run_cmd` 通过 shell（`cmd /S /C` / `sh -c`）执行**：依赖 ShellQuote 正确转义。ShellQuote 已处理双引号和单引号，但若 git 子命令路径含特殊 unicode 字符可能出问题。短期可接受（白名单已堵住绝大多数攻击面），长期可换 CreateProcess/`posix_spawn` 直接传 argv 数组
- **search_text 全仓库扫描没有 cache**：当前每次调用 `git ls-files` 然后逐文件 read，大仓库（~2 万文件）一次可能耗 1~2 秒；agent 多步会累积。可接受 —— 工具调用本来就是 LLM 决策的慢路径
- **find_symbol regex 用 `std::regex`**：std::regex 是出了名的慢，但仓库 ~85k LOC 实测可控。若 Phase 7 实测成瓶颈再换 hand-rolled scanner
- **测试不覆盖真实 git 输出**：tmp 目录非 git 仓库，find_files/search_text/find_symbol/git_log 等只验证了"err handling + 参数校验"。真实输出格式与 LLM 的兼容性留到 Phase 7
- **未测大文件截断 / 二进制跳过的字节边界**：当前只测 NUL 字节场景；2 MiB 截断只在代码层有逻辑没单测覆盖（构造 2 MiB 测试文件 IO 成本太大）

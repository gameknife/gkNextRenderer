# #00019 AIService Agent 化 — Phase 3：Agent Loop + Tool Registry + 主线程 dispatcher

## 做了什么

搭建引擎层 agent 调度基础设施：工具接口、注册中心、主线程任务派发、多步 ReAct 循环。完全 mock 驱动可测试，不依赖真实 LLM / 网络。

### 新增组件

| 文件 | 职责 |
| --- | --- |
| `AI/IAITool.{hpp,cpp}` | `IAITool` 接口、`FToolCallContext`、`FAgentToolEvent` (call/result/error/final/cancelled 5 phase)、`FAgentEventSink` + `FInMemoryAgentEventSink`（thread-safe，UI 可 Drain） |
| `AI/ToolRegistry.{hpp,cpp}` | name → `unique_ptr<IAITool>` 映射，`BuildSchemas` 给 LLM |
| `AI/MainThreadDispatcher.{hpp,cpp}` | thread-safe 队列：`Submit` 投递、`SubmitAndWait(timeout)` 阻塞、`DrainOnce` 主线程批量执行；异常透传到 future |
| `AI/AgentLoop.{hpp,cpp}` | 主 ReAct 循环、fallback tool call 解析、grounding 重试、cancel 检查 |

### 关键设计点

- **provider 注入而非耦合 FAIService**：`FChatProviderFn = std::function<FChatResponse(const FChatRequest&)>`，让 mock 测试直接传 lambda；生产里 `FEditorAIService` 会包 `[&](req){return aiService.Chat(req);}`
- **fallback tool call 解析**：模型若用 markdown ` ```json {"name":..., "arguments":...} ``` ` 或裸 JSON 输出而非 OpenAI `tool_calls`，照样能解析（支持 `name`/`tool` 别名 + `arguments`/`args` 别名 + 数组形）
- **grounding 启发式（修正版）**：只要 LLM **曾尝试** tool call（即使工具名拼错），就不再注入 reminder —— 模型已知有工具，让 ERROR 消息本身指导它。原始设计用 `toolCallsExecuted > 0`，被测试用例打脸后改成 `anyToolCallRequested`（更准确捕捉模型意图）
- **主线程 marshal**：`IAITool::RequiresMainThread()=true` 时 agent 把 Execute 包成 task 投到 dispatcher，`SubmitAndWait(timeout=5s)` 同步等返回；异常通过 promise 的 set_exception 透传
- **取消**：agent loop 每步迭代前查 `cancelFlag`，cancel 后立即返回带 `cancelled=true` 的结果
- **maxSteps 安全网**：默认 12 步上限；触顶返回 `maxStepsExceeded=true` + transcript

### 测试覆盖（11 case / 46 断言）

- ToolRegistry 注册/查找/Schema 构建
- 单 tool call → final 链
- unknown tool 返回 ERROR 给 LLM 让它继续
- tool 抛异常 → "ERROR: tool threw exception: ..." 透传给 LLM
- maxSteps 强制截断
- grounding：LLM 直接 final 无 tool → 注入 reminder 再来一轮成功
- cancel flag 在步与步之间生效
- fallback 解析：```json fence、bare object、bare array、纯文本（应返回空）
- MainThreadDispatcher：worker 线程 Submit → 主线程 DrainOnce 执行 + 返回 future
- agent loop + dispatcher 端到端：worker 跑 agent，主线程 drain，验证 main-thread 工具确实在 main thread 执行

## 风险与遗留

- **未触达真实 LLM**：所有测试用 mock provider；真实 small model（gemma 4 E4B）在工具调用稳定性、JSON 严格度上的表现需要 Phase 7 接入后实测调参
- **HttpPostJson 不可中断**：当前 cancel 只在步之间检查；模型正在等响应时 cancel 不会立即中断 HTTP。Phase 6 UI 接入时若用户抱怨"按了停止还要等几秒"，给 curl 加 progress callback 或换 curl multi
- **MainThreadDispatcher 没有任务优先级**：FIFO 简单队列，DrainOnce 一次性 swap 全部。如果主线程渲染卡了，工具任务堆积没问题；如果工具任务本身很慢（如 load_scene），会阻塞下一帧。Phase 5 编辑器工具实现时如发现热点，给 DrainOnce 加预算上限
- **grounding reminder 默认是英文**：考虑到工程师调试需要日志可读，先用英文。如果实测对中文模型干扰大，再让 FEditorAIService 覆盖为中文版
- **fallback 解析只看第一个 fence**：模型连续输出多个 fence 时会丢后面的。可接受 —— 模型不该一次发多个 fence，OpenAI 协议 tool_calls 才是正路

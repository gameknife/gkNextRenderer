## 做了什么

- `GoalSystem::Summarize` 改为读取 `FProjectState` 并本地计算分数：`overallProgress` 为基础，交付加分、残留 bug 扣分。
- LLM 结算 prompt 改为只生成一句点评，不再让 LLM 编 0-100 分数。
- 无 LLM / agent-validation 路径直接生成包含真实仪表、bug、交付状态和本地达成度的结算文本。
- 结算后生成 `nextBriefingContext_`，保留昨日目标、分数、仪表、bug 和交付状态；次日 `BeginDay` 会把这段残留上下文注入晨会目标生成 prompt。
- agent-validation 下提高 StudioSim time scale，允许 `gnb shot` 在几秒内跑到 Review 验证结算路径。

## 改动文件

- `src/Application/Game/StudioSim/GoalSystem.h`
- `src/Application/Game/StudioSim/GoalSystem.cpp`
- `src/Application/Game/StudioSim/StudioSimGameInstance.cpp`

## 验证

- `.\gnb.bat build StudioSim`：通过。
- `.\gnb.bat shot --target StudioSim --scene assets/scad/office.scad --frames 1800`：通过，日志确认进入 Review，并输出 `本地达成度 47/100`。

## 风险/遗留

- 多天 carry-over 已接入 prompt，但 agent-validation 没有自动点击 Next day；需要交互运行验证次日晨会文案实际利用残留上下文。
- 高 time scale 验证下会议真实秒对白节拍可能拖住参会者更久，正常交互时影响较小；后续可把聚集对白节拍也改成可随 time scale 调整。

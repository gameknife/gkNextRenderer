# #00021 AIService Agent 化 — Phase 5：编辑器工具集

## 做了什么

把 `FEditorScriptExecutor` 的命令面包成 `IAITool`，让 agent loop 能直接操作场景。设计上选择**复用 EditorScript 文本路径**而非重新实现节点 ECS 调用 —— `FEditorScriptExecutor::ExecuteScriptText` 已经处理了 tokenize / undo group / DEFERRED high-risk / 错误日志，工具层只需把 JSON 参数 format 成命令行字符串。

### 工具清单（17 个，全部 RequiresMainThread = true）

**查询（4）**——直接访问 `Scene` API，不走 EditorScript：
- `scene_list_nodes(pattern?, max=80)` — 节点列表，支持名称子串过滤，超限尾巴提示总数
- `scene_get_node(node)` — 单节点详情：pos / rotation_euler_deg / scale / components
- `scene_get_selection()` — primary id + 完整选中列表
- `scene_summary()` — 节点总数 + 选中 + component-type 直方图

**修改（10）**——format 成 EditorScript 一行调用 `ExecuteScriptText`，撤销 / 重做 / log 全继承：
- `scene_select` / `scene_rename` / `scene_delete` / `scene_duplicate`
- `scene_move(x,y,z)` / `scene_rotate(x,y,z)` / `scene_scale(x,y,z)`
- `scene_set_property(node, component, property, value)`
- `scene_rename_pattern(search, replace)`
- `cvar(command)`

**动作（1）**——含 high-risk 二次确认：
- `scene_action(name, arg?)` — `load_scene`/`add_scene`/`focus_selected`；`load_scene` 被 executor 标记 high-risk，`deferHighRiskActions=true` 时不立即执行，返回 `DEFERRED: <description>` 让 FEditorAIService 加入 `pendingActions_` 等用户确认

**逃生口（2）**——给 LLM 应付复杂场景：
- `run_editor_script(script)` — 多行 EditorScript 文本
- `run_javascript(code)` — QuickJS eval（`Editor.*` helpers 全可用）

### 关键设计点

- **`FEditorContextProvider = std::function<EditorContext*()>`**：`EditorContext` 是编辑器 frame tick 的临时栈对象，工具用 lambda getter 在每次 Execute 时取最新值；非 frame 期间返回 nullptr，工具回 "ERROR: editor context unavailable"
- **`QuoteForScript`**：参数含空格 / `"` / `\` / `#` 时用双引号包裹并转义 backslash + 内层 quote，匹配 `Tokenize` 的反向逻辑
- **drain-then-execute**：每次 Execute 前先 `TakeLog()` / `TakeDeferredActions()` 清空残留，再 ExecuteScriptText，再收集本次产生的输出，避免跨调用串扰
- **null-safety**：注册时 engine / executor / contextProvider 为 null 的对应 bucket 直接跳过；运行期工具 Execute 自检并返回 ERROR
- **enable flags**：`FEditorToolsOptions` 4 个开关（query/mutation/action/escape）让 MagicaLego 等下游能裁剪暴露面

## 风险与遗留

- **无单元测试**：EditorTools.cpp 直接依赖 `Scene`/`Node`/`FEditorScriptExecutor`/QuickJS，链接进 `gkNextUnitTests` 需要拉入整个 gkNextEditor 源码集合；性价比太低。Phase 7 端到端测试用真实 NextEngine + 本地 llama 全链路验证
- **DEFERRED 路径与 FEditorAIService 的对接尚未实现**：Phase 5 只产生 `DEFERRED: <desc>` 字符串返给 LLM，真正的"加入 pendingActions_ 等用户确认 UI"的桥接代码在 Phase 7 (#00023) 切换 FEditorAIService 主路径时一起做
- **`set_property` 的 value 序列化是字符串**：vec3 通过 `"x,y,z"` 文本传，依赖 `PropertyAccessor` 解析。LLM 偶尔可能传 `[1,2,3]` JSON 数组 —— ArgString 已转为 `"[1,2,3]"`，但 PropertyAccessor 是否吃这种格式没验证。Phase 7 实测时若失败，给 set_property 加专门的数组 → 逗号格式化
- **`run_javascript` 不支持读取返回值**：QuickJS eval 结果只能通过 `Editor.log(...)` 间接拿到。可接受 —— LLM 真要拿数据应该用 query 工具
- **`scene_get_component_schema` 没做**：spec 原计划包含此工具用 entt::meta 反射动态导出组件属性表。当前先靠 LLM 直接试 `set_property` + 错误反馈学习。如果实测发现 LLM 频繁猜错属性名，Phase 7 再补

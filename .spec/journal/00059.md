## 做了什么

- 新增 `r.sharc.debugMode=4`，在 SHARC Query pass 中显示 visible surface 对应的 cached radiance。
- 在 primary hit 后直接用 `hitPrimaryVertex_` 的 world position / normal 调 `SharcQuery`，命中后把 cached radiance 写入 debug 输出；同一个 SHARC voxel 内得到相同 cache 值，因此画面会按 hash grid 尺寸呈现块状马赛克。
- 抽出 `WriteSharcDebugOutput()`，复用 occupancy 与 radiance debug 输出的 GBuffer 写入。
- 更新 `r.sharc.debugMode` CVar 说明和 SHARC 剩余工作文档。

## 改动文件

- `assets/shaders/Core.SharcQuery.comp.slang`
- `assets/shaders/common/PathTracingRenderer.slang`
- `src/Engine/Runtime/Config/EngineCVars.cpp`
- `docs/plans/sharc-integration-remaining-work.md`

## 验证

- `.\gnb.bat build gkNextRenderer`：通过；官方 `SharcCommon.h` 仍有既有 out parameter warning。
- `.\gnb.bat build gkNextUnitTests`：通过。
- 临时设置 `r.sharc.enable=true`、`r.sharc.debugMode=4` 后运行 `.\gnb.bat shot --scene assets/models/playground.glb --frames 180`：通过，截图保存到 `out/build/windows/screenshots/agent_validation_sharc_radiance_debug.jpg`。
- 肉眼检查截图：场景表面显示按 SHARC grid 量化的 radiance 色块。playground 的 cache 多数为 sun/sky 照明，因此颜色以灰阶为主，这是当前 cache 内容的预期表现。

## 风险与遗留

- debugMode=4 显示的是 SHARC cache 中的 radiance，不包含材质 albedo；彩色材质场景下不一定显示材质色。
- 当前官方 SHARC update 仍是 MVP 接入，cache 覆盖率和颜色质量会随后续完整 throughput path-loop 改进。

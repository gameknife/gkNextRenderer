# #00023 AIService Agent 化 — Phase 7：FEditorAIService 主路径切到 agent 模式

## 做了什么

把 `FEditorAIService::GenerateAsync` 从"单轮 LLM + 抽 markdown 代码块"切换到 Phase 3 的 `FAgentLoop` 多步工具调用。把 Phase 4 (RepoTools) + Phase 5 (EditorTools) 一次性注册进引擎可用的 ToolRegistry。**默认 `useAgentLoop=true`**，但保留 legacy 路径作为 fallback。

### 数据流

```
AIPanel tick:
  service.SetCurrentContext(&ctx)       ← stack-scoped frame ctx 暴露给 tools
  service.PumpMainThread()              ← dispatcher.DrainOnce() + take deferred → pendingActions_
  ... 渲染 ...
  service.SetCurrentContext(nullptr)    ← 防 stale 指针

User clicks Send → service.GenerateAsync(prompt, ctx):
  cancelRequested_ = false
  if (useAgentLoop && SupportsTools):
      → RunAgentLoopAsync   (worker thread)
  else:
      → RunLegacyAsync       (existing path)

Worker thread (RunAgentLoopAsync):
  seed = [System(BuildAgentSystemPrompt), User(prompt)]
  FAgentLoop::Run(seed, toolRegistry_, ai->Chat, opts,
                  &agentEventSink_, &dispatcher_, &cancelRequested_)
    ↓ for each step:
      provider.Chat → tool_calls?
        no  → final → emit event + done
        yes → for each call:
                if RequiresMainThread: dispatcher.SubmitAndWait(5s) → blocks worker
                                       (main thread drains in next AIPanel frame)
                else: run inline (read-only repo tools)
                append tool message → next loop
  shape FAgentResult → FAIResponse → pendingResponse_

AIPanel sees hasPendingResult → ConsumePendingResult:
  if useAgentLoop: skip ExtractFromResponse (final text is plain summary)
                   status = Done | Waiting confirmation
```

### Tool Registry

`EnsureToolRegistry()` 构造时一次性注册：
- `RegisterRepoTools(reg, {repoRoot=".", enableAll=true})` — 8 个仓库探索工具
- `RegisterEditorTools(reg, {engine, executor, contextProvider, defer=true})` — 17 个编辑器工具

`contextProvider = [this](){ return currentContext_; }` — 取最新值，worker 在 dispatcher 主线程回调里调它，拿到当前帧的 valid ctx。

### Agent System Prompt（精简版）

从 ~250 行（scene table + asset catalog + property reflection 全塞）降到 **~20 行规则 + 短选中快照**。LLM 现在被引导通过工具按需取信息，而不是被一次性灌满。

### DEFERRED 路径

`EditorTools.cpp::RunScriptLine` 移除 `TakeDeferredActions()` 调用 — 留给 `FEditorAIService::HarvestDeferredActions()` 在每帧 PumpMainThread 时统一推到 `pendingActions_`，UI 弹确认条的流程不变。

### Legacy fallback

`useAgentLoop=false`（ai_config.json 显式切换）或 provider 不支持 tools 时自动回退到旧的 `RunLegacyAsync` 路径，保持完全行为不变 — 用户随时可对比新旧两种模式。

## 风险与遗留

- **未端到端实测**：本 turn 没启动 gkNextEditor + 本地 llama-server 跑真实 prompt。所有路径已经类型/链接检查过；Phase 9 集成测试会触发真实链路
- **小模型 tool-call 稳定性未知**：Gemma 4 E4B 对 OpenAI tool_calls 的支持质量待验证。`FAgentLoop::ParseFallbackToolCalls` + grounding 重试已是兜底；如果实测失败率高，再加 few-shot 到 BuildAgentSystemPrompt
- **`SetCurrentContext(nullptr)` 在 panel close 时不会被调**：如果用户关掉 AI Panel 而 agent worker 仍在跑，contextProvider 返回 nullptr → 工具回 ERROR → LLM 收到错误。可接受 —— 工具调用本来就该应对 frame-gap
- **deferred actions 收集时机**：当前在 PumpMainThread 全 drain。如果 agent loop 单次 ExecuteScriptText 产生 high-risk，它会立刻被 take 到 pendingActions_，但 agent loop 还在等下一步 LLM 响应，用户可能在这期间确认/取消该 action。这是 by design — 不阻塞 agent，pendingActions_ 与 agent 状态解耦
- **`scene_action(load_scene)` 后 agent 该怎么做？** 当前工具返回的日志含 "Deferred high-risk action" 字样（由 executor 写入），agent 应理解为"已排队"。如实测发现模型不理解，改 EditorTools 在 RunScriptLine 后探测 executor 是否新增 deferred 并 format 一行 hint 给 LLM
- **取消粒度**：cancelRequested 只在 agent loop 步与步之间检查。如果模型在某步等 HTTP 响应 30s，用户按 Stop 仍需等响应完才能中止。Phase 6 UI 已经 ready，等模型层支持 stream cancel 再补

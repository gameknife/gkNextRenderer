# #00017 AIService Agent 化 — Phase 1：LLM 协议升级

## 做了什么

把 `FAIService` 从"单 prompt-in/text-out"升级到 OpenAI 兼容的 chat + tool calling 协议，为后续 agent loop 打基础。所有现有 provider 继续工作，旧 `GenerateText` 行为零变化（内部已委托新 `Chat` 路径）。

### 新增数据结构（AIChat.hpp）

- `EChatRole` { System, User, Assistant, Tool }
- `FChatMessage` + 工厂方法 `System/User/Assistant/ToolResult`
- `FToolCall { id, name, argumentsJson }`
- `FToolSchema` + `FToolParam` + `EToolParamType`
- `FChatRequest { messages, tools, model, temperature, maxTokens }`
- `FChatResponse { success, content, toolCalls, finishReason, errorMessage, usage }`

### 新增序列化函数（AIChat.cpp）

- `BuildOpenAIChatRequestBody` / `ParseOpenAIChatResponse` — Zhipu/DeepSeek/Ollama-with-tools/将来 LocalLlama 共用
- `BuildGeminiChatRequestBody` / `ParseGeminiChatResponse` — 翻译 system → systemInstruction、tool calls ↔ functionCall、tool result ↔ functionResponse；arguments 在 OpenAI 是 JSON string，在 Gemini 是对象，已分别处理
- `BuildOllamaGenerateRequestBody` / `ParseOllamaGenerateResponse` — legacy /api/generate 路径，无 tool，回退用

### 接口扩展

- `IAIProvider` 新增纯虚 `Chat(FChatRequest) → FChatResponse` + `SupportsTools()`
- 4 个 provider 都实现 Chat；旧 `Generate(prompt)` 改为 thin wrapper 调 Chat
- `FAIService` 暴露 `Chat()` + `SupportsTools()`
- 4 个 provider 的 curl 重复代码抽成 `HttpPostJson(url, body, headers)` helper

### 测试（59 断言 / 7 case，全绿）

- OpenAI 请求体：messages / model / temperature / max_tokens / stream / tools 数组 + required 字段
- assistant tool_calls 序列化往返 + tool 角色的 tool_call_id/name 字段
- OpenAI 响应解析：content + tool_calls（string 形 + object 形 arguments 都支持）+ usage + error
- Gemini 请求体：system 升级到 systemInstruction，functionDeclarations 翻译
- Gemini 响应：functionCall 解析 + 自动合成 id + usageMetadata
- Ollama legacy generate prompt 拼接

## 风险与遗留

- **Gemini 翻译未充分实战验证**：tests 只验序列化结构，没打过真实 Gemini API。Phase 7 切换到 agent 时若 Gemini 返回的 tool 结构有边角差异，再补 case
- **Ollama tool path 未实战**：当前实现是"有 tools 就走 /v1/chat/completions，否则走 /api/generate"。老 Ollama 版本可能不支持 /v1 endpoint；遇到时在 #00019 加 SupportsTools 探测
- **HttpPostJson 没有取消支持**：Phase 3 agent loop 需要 cancel；届时给 HttpPostJson 加 cancel flag 或换 curl multi
- **assistant tool_calls 序列化时 content 总会写空串**：OpenAI 严格规范下 assistant message with tool_calls 应允许 content=null。当前用空字符串，主流 server 都接受；如某 provider 严格拒绝，再特判

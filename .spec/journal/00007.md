## 做了什么

- 将 `gnb.toml` 的 `[vcpkg].ref` 从 `2025.12.12` 升级到官方 release tag `2026.04.27`。
- 将 `vcpkg-configuration.json` 的 default registry baseline 绑定到 `2026.04.27` 的 peeled commit：`56bb2411609227288b70117ead2c47585ba07713`。
- 修复 `gnb setup` 只 checkout vcpkg 仓库但不更新 `.vcpkg/vcpkg.exe` 的问题：现在会读取 `scripts/vcpkg-tool-metadata.txt`，当本地 tool 版本与 checkout 期望的 `VCPKG_TOOL_RELEASE_TAG` 不一致时自动重新 bootstrap。
- 适配 vcpkg 2026.04.27 带来的 ImGui 1.92.7 API 变化：
  - FreeType 字体 loader 从 `FontBuilderIO/GetBuilderForFreeType` 迁移到 `SetFontLoader(GetFontLoader)` + `FontLoaderFlags`。
  - `ImFont::FontSize` 使用处兼容 `ImFont::LegacySize`。
  - `ImGui::Combo` 回调签名改为新版 `const char* (*)(void*, int)`。
- 处理验证过程中暴露的旧 CMake cache 问题：新版 zlib 在 Windows static triplet 下链接库名为 `zs.lib`/`zsd.lib`，旧 build dir 仍缓存 `zlib.lib`/`zlibd.lib` 会导致链接失败；clean configure 后正常解析。

## 风险 / 遗留

- `go test ./...` 中 `tools/gnb/internal/fetcher` 的 `TestUntarPreservesSymlink` 在当前 Windows 会话失败，原因是进程没有创建 symlink 权限：`A required privilege is not held by the client`。其它 Go 包通过，失败点与本次 vcpkg bootstrap 逻辑无关。
- 从旧 vcpkg baseline 升级到 2026.04.27 时，如果保留旧 CMake cache，可能继续引用旧库名（如 `zlib.lib`）；本次已确认 `--clean` 后配置正确。遇到同类链接缓存问题应先 clean build dir。

## 做了什么

- 定位到官方 SHARC query 缺少 segment length 约束：官方集成要求 path segment 短于当前 voxel size 时继续 trace，当前代码在短距离二次命中时仍直接查询 cache，容易把邻近体素 radiance 漏到当前路径上，表现为 SHARC on 偏亮。
- 给 `FPathTracingRenderer::CanUseSharcAtBounce` 增加 `segmentLength` 参数，并在 query 前用 `SharcGetVoxelSizeAt(vertex.Position)` 过滤短 segment。
- 将 SHARC hit/miss debug 着色中深层 bounce 的 `1000` 强度改为普通 `1`，避免 debug 模式自身造成过曝。

## 改动文件

- `assets/shaders/common/PathTracingRenderer.slang`

## 验证

- `.\gnb.bat build gkNextRenderer`：通过；官方 `SharcCommon.h` 仍有既有 out parameter warning。
- `.\gnb.bat build gkNextUnitTests`：通过。
- 临时打开 SHARC 后运行 `.\gnb.bat shot --scene assets/models/playground.glb --frames 180`：通过，日志包含 `uploaded scene [playground.glb] to gpu` 与 SHARC cache 分配。
- 修复前后截图亮度统计：
  - SHARC off：平均亮度 124.21，`luma>=245` 为 0.016%。
  - 修复前 SHARC on：平均亮度 127.62，`luma>=245` 为 0.015%。
  - 修复后 SHARC on：平均亮度 123.68，`luma>=245` 为 0.012%。

## 风险与遗留

- 当前修复解决短 segment cache 泄漏和 debug 过曝；完整官方 throughput path-loop 仍未接入。
- 还没有做室内薄墙场景的漏光/ghosting 压力测试，后续 SHARC 质量验证中继续跟踪。

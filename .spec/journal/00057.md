## 做了什么

- 将 NVIDIA-RTX/SHARC 官方 shader 头 vendored 到 `assets/shaders/third_party/sharc/`，并保留官方 `License.md`。
- 用官方默认 stride 替换自研 SHARC buffer 布局，新增 `SharcRuntimeParameters` 承载引擎运行时 CVar。
- 将 `assets/shaders/common/Sharc.slang` 改为官方 SHARC adapter：Slang 侧用 BDA 指针包装官方 `RWStructuredBuffer` 访问，Resolve 调 `SharcResolveEntry()`，Update/Query 分别接入 `SharcUpdateHit()` 与 `SharcGetCachedRadiance()`。
- 更新 shader 构建与 hot reload 依赖，让 `Core.Sharc*` 和 `Util.SharcCompileTest` 使用官方 SHARC define，并把 `third_party` shader 头纳入依赖扫描。
- 更新 `PathTracingRenderer` 的 SHARC buffer 分配、参数写入、默认 CVar 与 probe padding，保持默认 `r.sharc.enable=false`。
- 接入 occupancy debug view（`r.sharc.debugMode=3`），用于确认官方 hash grid 有实际写入。
- 更新 SHARC 计划文档，标注原自研简化版已废弃、官方 MVP 已接入，剩余性能/质量验证继续跟踪。

## 验证

- `.\gnb.bat build gkNextRenderer --reconfigure`：通过。
- `.\gnb.bat build gkNextUnitTests`：通过。
- `.\out\build\windows\bin\gkNextUnitTests.exe`：全量一次 61/62 通过，`Dynamic Physics Offset Uses Local Space` 发生 SIGSEGV；随后单独重跑该测试通过，判断为现有顺序性/偶发问题，需后续跟踪。
- `.\gnb.bat shot --scene assets/models/playground.glb --frames 120`：默认 SHARC off 通过，日志包含 `uploaded scene [playground.glb] to gpu`。
- 临时在构建输出 `cvar_user.json` 打开 SHARC 后，`.\gnb.bat shot --scene assets/models/playground.glb --frames 180` 通过，cache 分配日志正常，画面无黑屏/明显漏色。
- `r.sharc.debugMode=3` 下 occupancy debug 截图可见稀疏绿色命中，说明官方 hash grid 有写入。

## 风险与遗留

- 当前是官方 SHARC MVP 接入：能编译、运行、写入 cache 并 query，但 Update path 仍是兼容式单点 accumulate，尚未完整重写为官方建议的 `SharcInit -> SharcUpdateHit/Miss -> SharcSetThroughput` 多段 path-loop。
- 尚未证明 GPU timer 性能收益或同 frame budget 噪声收益。
- 高级质量项（SH encoding、material demodulation、responsive lighting、stale/sample-count heatmap）仍未接入。
- 官方 `License.md` 已随头文件 vendored；分发/发布合规仍需项目方确认 NVIDIA RTX SDKs LICENSE 条款。

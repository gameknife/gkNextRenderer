# #00019 AIService Agent 化 — Phase 3：Agent Loop + Tool Registry

## 背景

参考 [gnb chat_tools.go](../../tools/gnb/internal/dashboard/chat_tools.go) 的多步 ReAct 循环，在引擎层建一套通用 agent 调度，让 LLM 通过 tool 调用主动获取信息 / 修改场景，替代当前"一次性塞 system prompt + 抽 markdown 代码块"的模式。

## 范围

### In Scope

- 新增 `src/Engine/Runtime/Subsystems/AI/IAITool.hpp`：
  ```cpp
  struct FToolCallContext {
      class FMainThreadDispatcher* mainThread = nullptr;
      std::function<void(const std::string&)> logCallback;
      std::atomic<bool>* cancelFlag = nullptr;
  };
  class IAITool {
  public:
      virtual ~IAITool() = default;
      virtual std::string Name() const = 0;
      virtual FToolSchema Schema() const = 0;
      virtual bool RequiresMainThread() const = 0;
      virtual bool IsHighRisk() const { return false; }
      virtual std::string Execute(const nlohmann::json& args, FToolCallContext& ctx) = 0;
  };
  ```
- 新增 `FToolRegistry`：name → unique_ptr<IAITool> 映射 + `BuildSchemaList()` 给 LLM
- 新增 `FAgentLoop`：
  - 入口 `FChatResponse Run(std::vector<FChatMessage> seed, FToolRegistry&, FAgentOptions, FAgentEventSink&)`
  - 主循环：调 provider.Chat → 解析 tool_calls → 派发 → 把 `{role: tool, name, toolCallId, content}` 追加回 messages → 重复
  - 上限 `maxSteps`（默认 12）
  - **解析容错**：移植 gnb 的 `parseNativeChatToolCall` —— 模型未严格输出 JSON 时，正则抓 `{"name": ..., "arguments": ...}` 形式
  - **强制 grounding**：移植 `forcedToolContinuationReason` —— 若前一步只读了文件没修改场景，且模型已 final，自动注入"你必须用工具完成动作"再来一轮，最多 2 次
  - **取消**：每步前检查 `cancelFlag`
- 主线程派发器 `FMainThreadDispatcher`：
  - `Submit(std::function<std::string()>) → std::future<std::string>`
  - `NextEngine::Tick` 每帧 drain 队列执行
  - `RequiresMainThread()=true` 的工具通过它同步等待（带 5 秒超时）
- 事件接收器 `FAgentEventSink`：每步 emit `{step, phase, toolName, summary, detailJson}`，给 UI 用
- 单元测试 `Tests/AI/AgentLoopTests.cpp`：mock provider + 3 个 mock tools，覆盖：多步成功 / 步数上限 / 解析容错回退 / grounding 重试 / cancel

## 验收

- `gkNextUnitTests "[AI][AgentLoop]"` 全绿
- mock 场景下 agent 能完成 6+ 步 tool chain

## 风险

- 主线程 dispatcher 死锁：dispatcher 必须非阻塞投递，agent 侧 future.wait_for 带超时；超时降级为返回 error 给 LLM
- 多线程下 messages vector 拷贝成本：单次 chain 上限消息条数 200，超过截断历史

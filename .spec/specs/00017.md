# #00017 AIService Agent 化 — Phase 1：LLM 协议升级（tools schema）

## 背景

引擎当前 `FAIService` 是单轮 prompt-in / text-out（[AIService.cpp](../../src/Engine/Runtime/Subsystems/AIService.cpp)），无法承载 agent 多步工具调用。本 phase 升级协议层，让 provider 接口和数据结构能描述 OpenAI 兼容 tool calling（`tools` + `tool_calls` + `tool` role），为后续 agent loop 打基础。

## 范围

### In Scope

- 新增 `src/Engine/Runtime/Subsystems/AI/AIChat.hpp`：
  - `FChatRole { System, User, Assistant, Tool }`
  - `FToolCall { id, name, argumentsJson }`
  - `FChatMessage { role, content, name, toolCallId, toolCalls }`
  - `FToolParam { name, type, description, required }`、`FToolSchema { name, description, params }`
  - `FChatRequest { messages, tools, temperature, maxTokens, model }`
  - `FChatResponse { content, toolCalls, finishReason, usage }`
- 扩展 `NextAI::IAIProvider` 抽象基类：
  - 新增纯虚 `FChatResponse Chat(const FChatRequest&)`
  - 新增 `bool SupportsTools() const`
  - 保留旧 `Generate(prompt) → text` 接口，默认实现内部转 `Chat({{User, prompt}})`
- 现有 `FGeminiProvider` / `FZhipuProvider` / `FDeepSeekProvider` / `FOllamaProvider` 各自实现 `Chat`：
  - Zhipu / DeepSeek / Ollama → OpenAI `tools` schema 直传
  - Gemini → 翻译为 `functionDeclarations`，响应翻译回统一格式
  - `SupportsTools()` 各自返回正确值（Ollama 视模型而定，默认 true）
- 单元测试 `Tests/AI/AIChatProtocolTests.cpp`：
  - mock HTTP（用现有 test util），验证每个 provider 请求体 JSON 结构正确
  - 验证响应里 `tool_calls` 数组解析为 `FChatResponse::toolCalls`

### Out of Scope

- 本地 llama provider（→ #00018）
- agent loop（→ #00019）
- UI 改动

## 改动文件

- 新：`src/Engine/Runtime/Subsystems/AI/AIChat.hpp`
- 改：`src/Engine/Runtime/Subsystems/AIService.hpp/.cpp`

## 验收

- `gnb build --reconfigure` 通过

## 风险

- Gemini 翻译层有差异：函数响应字段 `functionCall.args` 是对象不是字符串，需 stringify
- Ollama 老版本不支持 tools：探测失败时 `SupportsTools()` 返回 false 并降级

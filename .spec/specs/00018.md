# #00018 AIService Agent 化 — Phase 2：本地 llama provider

## 背景

gnb 已通过 `gnb llm serve` 启动本地 llama-server（OpenAI 兼容，默认 `127.0.0.1:8765`，PID 文件 `external/llm/run/server.pid`）。引擎复用同一进程即可获得 agent 推理能力，无需自己嵌入 llama.cpp。

## 范围

### In Scope

- 新增 `NextAI::FLocalLlamaProvider`（`src/Engine/Runtime/Subsystems/AIProviders/LocalLlamaProvider.{hpp,cpp}`）：
  - 实现 `IAIProvider::Chat / ChatStream`（OpenAI schema 直传，参考 [gnb client.go](../../tools/gnb/internal/llm/client.go) 实现）
  - 支持流式 SSE 解析（`text/event-stream`，`data: ...` 行 → 增量回调）
  - 请求体默认带 `chat_template_kwargs.enable_thinking = false`
- PID 自动发现：
  - 工具函数 `TryReadLlamaPidFile(host, port, modelId) → bool`，读 `external/llm/run/server.pid` 第 2/3/4 行
  - `FLocalLlamaProvider` 构造时优先用 PID 文件，缺失则回退 config
- `assets/configs/ai_config.json`：
  - 新增段 `"localllm": { "endpoint": "http://127.0.0.1:8765", "model": "", "autoDiscoverPid": true }`
  - `"provider"` 默认值改为 `"localllm"`（不破坏老配置：未配置 localllm 段时 fallback 现有 provider）
- `AGENTS.md` 在 "Local LLM (gnb llm)" 节追加一段："引擎 `FAIService` 现复用同一 llama-server，无需独立模型进程"

### Out of Scope

- tool calling 解析容错（→ #00019 agent loop 里做）
- UI 改动

## 改动文件

- 新：`src/Engine/Runtime/Subsystems/AIProviders/LocalLlamaProvider.{hpp,cpp}`
- 新：`src/Engine/Runtime/Subsystems/AI/LlamaPidFile.{hpp,cpp}`
- 改：`src/Engine/Runtime/Subsystems/AIService.cpp`（provider 工厂注册）
- 改：`assets/configs/ai_config.json`
- 改：`AGENTS.md`

## 验收

- 手动跑：`gnb llm serve` → 启动 `gkNextEditor` → AI Panel 用本地模型完成一次基础对话（"列出场景里的节点名"等老 prompt 模式）
- `gnb build --reconfigure` + 单元测试通过
- PID 文件不存在时不崩溃，回退到 config endpoint

## 风险

- llama-server 切模型重启期间 PID 文件中途为空：`TryReadLlamaPidFile` 必须容忍并返回 false（让上层等下次轮询）
- 长 prompt + 流式响应可能超时：`HTTP::Client` 超时调到 5 分钟（对齐 gnb）
